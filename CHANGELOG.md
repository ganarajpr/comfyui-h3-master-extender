# Changelog

## Unreleased

- **H3 Shot Writer node, Extender `clips_in` and `run_mode` prompts_only.** New node `H3 Shot Writer (brief to shot lists)` (`shot_writer.py`, `prompts/shot_writer_*.md`): a free-form brief (clip-numbered lines, ranges, prose, dialogue in any language) becomes a timed shot list per clip (`clips` JSON output with a `raw` text per clip) plus a `story` summary. One plan call (cast, locations, per-clip goal and a state ledger folded in code, so armour, a ring or a dropped sword carry into every later clip) and one shot call per clip, with code checks (timing, dialogue script, words per shot, the founder's own lines verbatim, outfit named on first appearance) and one retry with the complaint. Reads `ref_image_1..9` (same names and `<Picture N>` numbering as the Extender) with `story_planner.picture_parts`. Requests carry a JSON schema (`response_format`) on chat completions. The Extender gets a lazy `clips_in` socket (appended last; used only while the clip list has no prompt), the `prompts_only` run mode (rewrites and writes the prompts, blocks `cache`/`last_frame`, renders nothing) and a panel button "Re-import from writer". Story Writer behaviour is unchanged. Tests: `tests/test_shot_writer.py`.

- **Pass-2 windowing is now for 1080p-class output only (founder decision 2026-10-22).** New COMBO input `pass2_chunk_when` (`above 720p` default | `always`), appended after `pass1_steps`. `above 720p`: pass 2 is windowed only when the pass-2 short side is over 800 px; 1280x720/736, 1344x768 and 720x1280 refine the whole clip in one pass (measured on a 15 s, 9-ref 1280x736 clip: whole-clip step ~30 s vs ~44 s for the 4-window refine, because the 22-frame overlaps add ~40% tokens). `always` is the old behaviour. `pass2_chunk_frames` 0 still means never window; dual sampling is unchanged. This changes the default at 720p. Logs `Pass 2: whole clip (pass2_chunk_when=above 720p, short side N px <= 800)` when it skips windowing. Panel row "chunk when"; the Performance line in metadata shows it.

- **`pass1_steps` (opt-in).** New INT input appended after `pass1_early_stop` (default 0 = full 8-step pass 1, byte-identical, same pass-1 cache fingerprint). k = 1..7 with HyperFlow 8-step and no dual sampling: pass 1 samples grid[:k+1], returns the model's clean x0 estimate, then the normal 3D upscale and the unchanged windowed pass-2 refine. Ignored (logged) with dual sampling or Turbo LoRA. `pass1_early_stop` without dual sampling is still a no-op. Panel: a `pass 1 steps` row under the engine controls plus presets `Standard \u00b7 pass 1 = 7 / 6 steps`.

- **Panel: Preset dropdown (Engine section, first row).** JS-only, no Python or INPUT_TYPES change, no widget moves, the dropdown itself is not serialized. Picking a preset writes the real widgets (accel_mode, hyperflow_file, curve refit, dual sampling, split step, early stop, pass-1/pass-2 resolution, pass-2 LoRA/steps, ...) and re-renders the panel. Presets: Standard, K4-K7 at 352p and K4-K7 at 480p, each with its measured 15 s time. The row shows Custom whenever the values match no preset; loading a workflow only reads, never writes. Table in `web/presets.js`; if it fails to load the panel is unchanged minus that row. Tests: `tests/test_presets.mjs`.

- **`accel_mode` option "HyperFlow 8-step · dual sampling"** (appended last; default and all existing values behave as before). Resolves to HyperFlow 8-step with dual sampling forced on, `dual_split_step` (2), no pass-2 LoRA and `pass2_chunk_frames` treated as 0 (whole-clip pass 2). Pass-1 fingerprint unchanged for existing modes and for this mode with early stop off. New example `MiniMax_H3_Master_Extender_Action_v2_DualSampling.json`; use prompts under 5,000 characters. Tests: `tests/test_dual_sampling.py`.
- **Fix: pass-1 early stop crashed** with `'CFGGuider' object has no attribute 'inner_model'` (ComfyUI drops it when `sample()` returns). The x0 now comes from the sampler callback and is mapped back through `guider.model_patcher.model.process_latent_out`.
- **HyperFlow dual sampling (opt-in).** New inputs, appended after `sparse_sink` so saved workflows keep their widget positions: `dual_sampling` (BOOLEAN, off), `dual_split_step` (INT 1-6, 2), `pass1_early_stop` (BOOLEAN, off). With `dual_sampling` on and HyperFlow 8-step, pass 2 runs HyperFlow's trained grid from index `dual_split_step` (2 = 6 steps from 0.9843) with no pass-2 LoRA and `pass2_denoise` ignored; `pass1_early_stop` also cuts pass 1 to `grid[:k+1]` and upscales the last step's x0 estimate (experimental: the upscaler was trained on clean latents). Turbo LoRA mode warns and runs normally. With the inputs at their defaults the code path, sigmas and pass-1 fingerprint are unchanged; `dual` enters the pass-1 fingerprint only with early stop on. The panel shows the toggles in HyperFlow mode only (split step and early stop while dual sampling is on) and old workflows load with the defaults. New example `MiniMax_H3_Master_Extender_HyperFlow_DualSampling.json` (pass 1 608x352, pass 2 1344x768, split 2). Tests: `tests/test_dual_sampling.py`, `tests/test_widget_migration.mjs`.

- **PDD 8-step mode removed; HyperFlow 8-step is the default engine.** `accel_mode` is now `HyperFlow 8-step` (default) | `Turbo LoRA`. The engine class is `MasterEngine` (was `PurePDDEngine`; file name unchanged) and `initialize_pdd_model` is `initialize_model`; the PDD head-bank branch, the PDD scheduler tail and the fallback sigmas are gone, and the engine start-up log now names the real mode and its LoRA/file. No widget moved: `pdd_file` keeps its slot as an inert, hidden STRING (any saved value, e.g. `minimax_h3_ref2va_pdd_acc_8step_comfyui.safetensors`, still validates and is ignored) and `pdd_nfe` keeps its slot as the Turbo LoRA step count (shown as "steps" in Turbo mode only; HyperFlow ignores it). Old saved workflows with `PDD 8-step` load as HyperFlow 8-step (`web/widget_migration.js: migrateAccelMode`), and an API graph that still sends `accel_mode: "PDD 8-step"` (e.g. `render_clip.py`) runs HyperFlow 8-step with a warning (`normalize_accel_mode`; `VALIDATE_INPUTS` skips the combo check for it). New defaults: `pass2_lora` = `h3\minimax_h3_DMAD_4step_full_lora_avg_rank_39_bf16.safetensors` (when present, else none), `pass2_lora_mode` = `replace engine LoRA`, `pass2_steps` = 4 (`hyperflow_file`, `hyperflow_curve_refit`, `semantic_bridge` and its alpha 0.12 are unchanged: already the founder's values). The pass-1 cache fingerprint no longer includes `pdd_file`, so existing pass-1 caches re-render once. Example workflows updated to the same layout (no PDD). **ComfyUI-MiniMax-H3-PDD-Acc is no longer needed**, and the `pdd_acc` model folder is no longer registered.

- **Per-clip reference pictures: a clip object in `clips_json` may carry `"refs": [i, j, ...]`**, 1-based indices into the job's `refs_json` pictures. That clip is conditioned only on those pictures, presented as its `<Picture 1..k>` in the listed order (so its prompt numbers its own pictures 1..k, not the job's slot numbers); a clip without `"refs"` gets every job picture exactly as before. The identity guide frame (`identity_continuity`) is still appended after the clip's pictures, as `<Picture k+1>`; motion context, smart offload and the single text encode are unchanged. `"refs"` enters the clip fingerprint and the pass-1 fingerprint only when present, so existing caches stay valid and a changed list never reuses an old pass 1. A bad list (not integers, a repeat, a number the job has no picture for) fails before any clip renders. Video/audio references are still shared by every clip, and the built-in prompt rewriter still writes against all job pictures (a warning says so). The log lists each such clip's pictures (`Clip N: per-clip refs [...]`). A clip with 2 of 7 pictures encodes and samples with 2 pictures' worth of reference tokens instead of 7.

- **Pass 1 only, and a pass-1 cache that survives pass-2 changes.** `pass2_resolution` gains a last choice, `off (pass 1 only)`: pass 2 is skipped and the pass-1 latent is decoded at the pass-1 size (`608x352`), or at 2x that with the X2 final decode (`1216x704`); chains and motion context work as before. The pass-1 (draft) chain on disk is now keyed on pass-1 inputs only: a per-clip fingerprint of prompt, duration, LoRAs, seed, pass-1 resolution, accel/turbo/HyperFlow/SLA/sparse settings, context lengths, semantic bridge, the reference pictures/videos/audio and the previous clip's fingerprint (so clip k's pass 1 still depends on clip k-1's). Changing the pass-2 resolution, pass-2 LoRA/steps, `final_decode` or switching pass 2 on/off no longer re-renders pass 1: the final clips are dropped, pass 1 is loaded (`Clip N: PASS 1 LOADED FROM CACHE ...`) and only the upscale, pass 2 and decode run. Only a pass-1 resolution change drops the pass-1 cache. With pass 2 off the single text encode runs at 1280x736 (720x1280 portrait), the size a 720p final uses, so a draft equals the pass 1 of a render finalised at 720p; the identity guide frame of clip k>1 still comes from clip k-1's decode, which is pass-2 output in a full render.

- **Story continuity**: the planner now returns an `end_state` for every clip (location, time and light, the exact last action, and each on-screen character's position, wardrobe, props and state). It is written into the clip's raw ask twice: as an `AT THE END OF THIS CLIP` block at its end, and as a `CONTINUITY - THIS CLIP OPENS EXACTLY WHERE CLIP N ENDED` block at the start of the next clip (only when clip N-1 is the planned clip right before it), so the writer of clip N has the exact state clip N-1 closed on in both `raw asks` and `final prompts` mode. A reply without an `end_state` counts as a failed check and gets the planner's one retry. With `final prompts` the writer also gets the last shot of the previous final prompt on its own. The continuity rules sit outside `prompts/planner.md` (the template's "visually self-contained" line is overridden in the message, not edited).
- **Wardrobe from the story, identity from the picture**: reference pictures are captioned as `Identity:` (face, build, skin tone, hair, age, marks) and `Outfit shown:`; captions cached before this are made again once. A Ref2VA writer is told the picture supplies identity only, to put the story's outfit (clip ask, then previous clip's end state, then story, then the picture's outfit only when all are silent) into `subject_definitions`, and to mark the subject `partially_preserved` in `retention_analysis` (identity retained, clothing replaced) without describing the old outfit or naming what is not worn. The planner is told the same (clothing from the story; `as on the reference` when the story is silent).

- **Fix**: the first plan now sees typed clips. - **Plan more**: raising `auto_clips` past the existing clip count plans only the new clips after the existing ones (continuation block, carried ledger state, numbering from the next clip). The planner's end-of-clip state is stored on each planned clip as `plan_end_state`.
- **Fix**: logging model or user text (an en dash, Devanagari...) raised UnicodeEncodeError on a cp1252 console. Our loggers now pass every record through `ConsoleSafeFilter` (typographic punctuation to ASCII, the rest as \\uXXXX); the panel and the stored clips keep the real Unicode.
